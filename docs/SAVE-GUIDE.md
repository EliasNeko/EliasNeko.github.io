# save 是什么意思

> 你说「save」，我就按下面这几件事一次做完，不再问你。

## 我会做的五件事

| 顺序 | 做什么 |
|---|---|
| 1 | 写入 `小鱼的记忆.md`（今天发生了什么） |
| 2 | 更新 `CHANGELOG.txt`（弹窗会显示） |
| 3 | 检查文件：有没有敏感文件混进仓库、脚本语法对不对 |
| 4 | 云端 / 本地同步检查：云端用户导到 `coffee-site/本地注册记录.json` |
| 5 | 推送（`git add` → `commit` → `push`，自动处理代理） |

## 你自己能按的按钮

双击 **`save.bat`**：它会做第 3、5 步（检查 + 提交 + 推送），代理没开会自动换一种方式推。

第 1、2、4 步需要我，因为要读上下文、判断写了什么。

## 改了公共脚本之后

`assets/js/chat.js`、`assets/js/live.js`、`coffee-site/member.js` 这些被很多页面共用。
改完必须把所有页面里的 `?v=20261023` 改成新版本号，否则**浏览器会一直用缓存里的旧文件**，表现为「明明改了却没生效」。

## 出问题时

- 推送失败：看 `save.bat` 的提示，或双击 `update-site.bat`
- 云端同步失败：可能是 Supabase 项目休眠，去后台点 Restore
