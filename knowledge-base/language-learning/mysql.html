MySQL：数据最终住在哪

表、行、列、索引、事务——学完后端，你总会需要它。

13 节难度 中等更新 2026-10-23

01它是什么

MySQL 是关系型数据库：数据放在表里，表由行和列组成，表和表之间用外键连起来。你的网站再漂亮，最后总得有个地方把「谁买了什么」记下来——那就是它。

同一类的还有 PostgreSQL、SQL Server、SQLite。学会一个，换另一个主要是语法细节的差别。

适合谁：学完后端、要做课程设计、或者想让会员数据别再存在 txt 里的人。

02装好、连上

Windows 装 MySQL Community Server，装的时候会让你设 root 密码，记下来。装完开命令行：

mysql -u root -p
SHOW DATABASES;
坑：装完提示「不是内部或外部命令」—— 要把 C:\Program Files\MySQL\MySQL Server 8.0\bin 加进 PATH，或者直接用开始菜单里的 MySQL Command Line Client。

不想装服务端也可以先用 SQLite 练语法，命令换成 sqlite3 test.db，其他基本一样。

03库、表、行、列

CREATE DATABASE coffee;
USE coffee;

CREATE TABLE orders (
    id      INT AUTO_INCREMENT PRIMARY KEY,
    name    VARCHAR(20) NOT NULL,
    item    VARCHAR(40) NOT NULL,
    price   DECIMAL(8,2) NOT NULL,
    created DATETIME DEFAULT NOW()
);

一个数据库里有很多表；一张表里每一行是一条记录；每一列规定了这个字段叫什么、什么类型、能不能空。

04类型怎么选

  • 整数：INT（普通）、BIGINT（很大）
  • 小数：钱一定用 DECIMAL(8,2)，别用 FLOAT——浮点数算钱会差几分钱
  • 字符串：VARCHAR(n) 变长，CHAR(n) 定长（像身份证号）
  • 时间：DATETIME 或 TIMESTAMP
坑：VARCHAR(20) 存不下 21 个字，严格模式下直接报错，宽松模式会偷偷截断——建表时长度留点余量。

05增、删、改

INSERT INTO orders (name, item, price) VALUES ("阿猫", "耶加雪啡", 32.00);

UPDATE orders SET price = 35.00 WHERE id = 1;

DELETE FROM orders WHERE id = 1;
坑（最重要的一条）：UPDATE 和 DELETE 不写 WHERE 就是全表改 / 全表删。执行前先用同样的 WHERE 写一条 SELECT，确认选中的是你要的那几行。

06查：WHERE、ORDER、LIMIT

SELECT name, item, price
  FROM orders
 WHERE price >= 20
   AND name = "阿猫"
 ORDER BY price DESC
 LIMIT 10;

执行顺序是 FROM → WHERE → ORDER BY → LIMIT，所以 WHERE 里不能用 SELECT 起的别名。

坑：NULL 不能用等号判断，要用 IS NULL / IS NOT NULL。

07聚合：COUNT、SUM、GROUP BY

SELECT item, COUNT(*) AS 杯数, SUM(price) AS 总额
  FROM orders
 GROUP BY item
 ORDER BY 总额 DESC;

GROUP BY 之后，SELECT 里只能出现「分组的列」和「聚合函数」，其他列没有意义。

坑：WHERE 过滤的是行，分组之后再过滤要用 HAVING：GROUP BY item HAVING SUM(price) > 100。

08JOIN：把两张表接起来

SELECT o.name, o.item, u.phone
  FROM orders o
  JOIN users u ON u.name = o.name
 WHERE o.price > 20;

JOIN 默认是 INNER JOIN，只保留两边都匹配上的行；要保留左表全部用 LEFT JOIN。

坑：忘了写 ON 条件会变成笛卡尔积——两张 1000 行的表查出 100 万行，服务器直接卡住。

09索引：快，但不是越多越好

CREATE INDEX idx_orders_name ON orders (name);

索引像书的目录：查 WHERE name = ? 不用翻全表。代价是写入变慢（每次都要维护目录）、占空间。

  • 经常出现在 WHERE / JOIN / ORDER BY 里的列，才考虑加
  • 区分度低的列（比如性别只有两三种）加了没什么用
  • 在索引列上套函数（WHERE YEAR(created) = 2026）会让索引失效
坑：用 EXPLAIN 看执行计划，type 是 ALL 就是全表扫描，说明索引没走上。

10事务：要么全成，要么全不成

START TRANSACTION;
UPDATE accounts SET balance = balance - 32 WHERE name = "阿猫";
UPDATE accounts SET balance = balance + 32 WHERE name = "小鱼";
COMMIT;
-- 中途出错就 ROLLBACK;

转账这种「两边必须一起变」的操作，必须包在事务里。中途任何一步失败，ROLLBACK 把前面做的全撤掉。

坑：MySQL 默认的 InnoDB 才支持事务；老式的 MyISAM 引擎不支持，建表时别选错。

11和 Java 连起来（JDBC）

String url = "jdbc:mysql://localhost:3306/coffee?serverTimezone=Asia/Shanghai";
try (Connection c = DriverManager.getConnection(url, "root", "密码");
     PreparedStatement ps = c.prepareStatement("INSERT INTO orders(name,item,price) VALUES (?,?,?)")) {
    ps.setString(1, "阿猫");
    ps.setString(2, "耶加雪啡");
    ps.setBigDecimal(3, new BigDecimal("32.00"));
    ps.executeUpdate();
}
坑：千万别把用户输入直接拼进 SQL 文本（拼接字符串），那是 SQL 注入的入口。一律用 PreparedStatement 的 ? 占位。
坑：连不上先看三件事：服务有没有启动、端口 3306 通不通、账号密码对不对。报 Public Key Retrieval is not allowed 就在 url 后面加 &allowPublicKeyRetrieval=true&useSSL=false（只在本机开发用）。

12动手项目：咖啡店订单表

要求：建 orders 表（谁、点了什么、多少钱、什么时候），插入 5 条测试数据，写三条查询：

  • 每个人一共花了多少（按人分组）
  • 卖得最好的三样（按商品分组、按杯数倒序、取前三）
  • 今天下的单（按日期过滤）

验收：三条查询结果和手算对得上；把 DELETE 写成不带 WHERE 时，先用 SELECT 验证过再执行。

13往哪走

把建表、增删改查、JOIN、索引用熟，就够做课程设计了。再往上可以看：备份（mysqldump）、慢查询日志、读写分离。

一句话：数据库不是「存东西的地方」，是「按规则存、按问题取」的地方——表设计得好，查询就短。
