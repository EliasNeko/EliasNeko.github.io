Rust：不靠垃圾回收的内存安全

它用「所有权」在编译期就把内存问题拦下来。学起来陡，但学完你会真正明白内存在干什么。

12 节难度 偏高更新 2026-10-23

01它是什么

Rust 是一门编译型语言，主打两件事：内存安全和不靠垃圾回收。C 和 C++ 里最容易出的问题（用了已经释放的内存、两个指针同时改一块数据），Rust 在编译的时候就给你拦下来。

代价是：你得先理解它的「所有权」规则，否则代码会一直编译不过。这一门课的重点就是这条规则，而不是语法。

适合谁：学完 C 或 Java，想弄明白「内存到底怎么管的」的人。Rust 找工作的岗位不算多，但学完再看别的语言，会清楚很多。

02装工具链

Rust 用 rustup 管工具链，一条命令装好编译器 rustc、包管理 cargo 和文档。

# Windows 去 rustup.rs 下载 rustup-init.exe，双击一路回车
# 装完开一个新终端
rustc --version
cargo --version

新建项目不要手写目录，用 cargo：

cargo new hello
cd hello
cargo run
坑：装完不重开终端，会提示找不到 cargo——环境变量要新进程才读得到。

03变量默认不能改

别的语言里变量随便改，Rust 默认不可变，要改必须写 mut。

fn main() {
    let x = 5;
    // x = 6;          // 编译不过：cannot assign twice to immutable variable
    let mut y = 5;
    y = 6;             // 可以
    println!("{x} {y}");
}

看着麻烦，其实是在帮你：一个变量如果从头到尾没变过，读代码的人就不用担心它中途被谁改了。

坑：let x = 5; let x = "abc"; 是允许的，这叫遮蔽（shadowing），不是改类型，是新变量盖住了旧的。

04所有权：一个值只有一个主人

Rust 的核心规则只有三条：每个值有且只有一个主人；主人离开作用域，值就被释放；值可以「借」给别人，但借的时候有规矩。

fn main() {
    let s1 = String::from("咖啡");
    let s2 = s1;              // 所有权从 s1 移到 s2
    // println!("{s1}");      // 编译不过：s1 已经被移走
    println!("{s2}");
}

这和 Java 的「两个变量指向同一个对象」不一样：Rust 直接把 s1 作废，避免两个地方同时释放同一块内存。

坑：整数、布尔、字符这类固定大小的类型会复制而不是移动，所以 let a = 1; let b = a; println!("{a}") 是能编过的。别拿这个规律去套 String。

05借用：& 和 &mut

不想交出所有权，就「借」：&x 是只读借用，&mut x 是可写借用。

fn len(s: &String) -> usize {
    s.len()
}

fn push(s: &mut String) {
    s.push_str("！");
}

fn main() {
    let mut s = String::from("好");
    println!("{}", len(&s));
    push(&mut s);
    println!("{s}");
}

规矩：同一时间，要么多个只读借用，要么一个可写借用。不能又要读又要写。

坑：这句规则会把你习惯的写法拦下来，比如「一边遍历一边往 Vec 里 push」。正确做法是先收集要改的东西，循环结束后再改。

06String 和 &str

String 是能增长的字符串（堆上），&str 是「借来的一段文本」，函数参数一般用 &str，因为 String 能自动转过去。

fn greet(name: &str) {
    println!("你好，{name}");
}

fn main() {
    let a = String::from("阿猫");
    greet(&a);        // String -> &str
    greet("小鱼");     // 字面量本来就是 &str
}
坑：不要写 fn f(s: String) 然后到处传引用——参数用 &str 更通用，调用方不用交出所有权。

07结构体和方法

struct Coffee {
    name: String,
    price: u32,
}

impl Coffee {
    fn new(name: &str, price: u32) -> Self {
        Self { name: name.to_string(), price }
    }
    fn describe(&self) -> String {
        format!("{} 卖 {} 元", self.name, self.price)
    }
}

fn main() {
    let c = Coffee::new("耶加雪啡", 32);
    println!("{}", c.describe());
}
坑：&self 是只读方法，&mut self 是能改字段的方法，self 会把对象吃掉。新手常把该用 &self 的写成 self，结果对象用一次就没了。

08枚举、match 和 Option

enum Drink { Coffee, Tea, Juice }

fn price(d: Drink) -> u32 {
    match d {
        Drink::Coffee => 32,
        Drink::Tea => 18,
        Drink::Juice => 22,
    }
}

Rust 没有 null，用 Option<T> 表示「可能有、可能没有」：

fn find(name: &str) -> Option<u32> {
    if name == "咖啡" { Some(32) } else { None }
}

match find("咖啡") {
    Some(p) => println!("{p} 元"),
    None => println!("没找到"),
}
坑：match 必须把所有分支写全，漏一个编译不过。这不是啰嗦，是逼你想清楚「没有的情况怎么办」。

09Result 和问号

会失败的操作用 Result<T, E>，不要用 unwrap() 糊过去——它一失败就直接 panic。

use std::fs;

fn read_name() -> Result<String, std::io::Error> {
    let text = fs::read_to_string("name.txt")?;
    Ok(text.trim().to_string())
}

fn main() {
    match read_name() {
        Ok(n) => println!("名字：{n}"),
        Err(e) => println!("读文件失败：{e}"),
    }
}
坑：? 只能用在返回 Result（或 Option）的函数里。写在 fn main() 里会报错，除非 main 也返回 Result。

10Vec 和 HashMap

use std::collections::HashMap;

let mut list: Vec<i32> = vec![3, 1, 2];
list.push(5);
list.sort();

let mut stock: HashMap<&str, i32> = HashMap::new();
stock.insert("咖啡", 10);
stock.insert("茶", 4);

if let Some(n) = stock.get("咖啡") {
    println!("咖啡剩 {n}");
}
坑：list[10] 越界会直接 panic；用 list.get(10) 拿 Option 才安全。

11动手项目：命令行待办

要求：做一个 todo 命令，支持 add 内容、list、done 编号，数据存 todo.txt，一行一条，完成的用 [x] 开头。

验收：加三条、列出来、完成第二条、再列出来；关掉终端重开，数据还在；文件不存在时不崩，当成空列表。

提示：

  • 读文件用 fs::read_to_string，文件不存在返回 Err，用 if let Ok 处理
  • 写文件用 fs::write，把整个 Vec 拼成字符串再写，别折腾追加
  • 命令行参数用 std::env::args()，第一个是程序名，从第二个开始才是你的参数

12往哪走

把「所有权」弄明白之后，再去碰 trait、泛型、生命周期，会顺很多。想做后端看 axum，想做命令行工具看 clap。

一句话：Rust 不是难在语法，是难在它不肯让你糊弄内存。糊弄不了，也就不会半夜被段错误叫醒。
