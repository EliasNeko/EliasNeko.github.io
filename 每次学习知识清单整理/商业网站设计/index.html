01网页是怎么到你屏幕上的

很多人学了一学期 HTML，还是说不清「你敲的那些尖括号，最后怎么就变成一张网页了」。这一节把这条路走一遍。

四个词，别混

因特网（Internet）全球的电脑连成的那张网。是路。
万维网（WWW）跑在这张网上的一项服务：用浏览器看网页。是路上跑的一种车。
网站一堆放在同一台服务器上、互相链接的网页。是一栋楼。
网页一个 .html 文件，浏览器读它、画它。是楼里的一个房间。

关系是：因特网 ⊃ 万维网 ⊃ 网站 ⊃ 网页。www.qq.com 是万维网上的一个网站，www.qq.com/index.html 是它的首页网页。

URL 拆开看

https://www.example.com:443/music/list.html?id=3&page=2#top
└─┬─┘   └──────┬──────┘└┬┘└──────┬──────┘└──────┬─────┘└┬┘
 协议        域名      端口     路径          查询参数  锚点
协议http / https（加密），还有 file://（本地文件，双击打开就是它）
域名服务器的门牌号，DNS 负责把域名翻译成 IP
端口一台服务器上有很多服务，端口区分它们。http 默认 80，https 默认 443，可以省略
路径服务器上文件的位置。大小写敏感——本地 Windows 不敏感，服务器敏感，这是上线翻车第一名
查询参数?key=value&key2=value2，给服务器带话
锚点#top，只在页面内部跳，不发给服务器

一次访问发生了什么

1你在地址栏敲网址，浏览器问 DNS：这个域名对应哪个 IP
2浏览器向那个 IP 的 80/443 端口发一个 HTTP 请求：GET /index.html
3服务器把 index.html 的内容原样发回来（状态码 200）
4浏览器读 HTML，遇到 <link> 和 <script> 就再去要 CSS 和 JS 文件
5浏览器把 HTML 变成 DOM 树、把 CSS 变成样式规则，算每个盒子放哪、多大，最后画到屏幕上
记住第 4、5 步：浏览器只认三样东西——HTML、CSS、JavaScript。你写的 React、Vue、Sass，最终都要变成这三样才有人看得懂。前端的尽头是这三样，退路也是这三样。

HTML 文档的结构

<!DOCTYPE html>              <!-- 告诉浏览器：我是 HTML5 -->
<html lang="zh-CN">          <!-- 根元素，lang 声明语言 -->
<head>                       <!-- 给浏览器看的信息，不显示在页面上 -->
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>蓝梦音乐网</title>
</head>
<body>                       <!-- 给人看的内容，全写在这里 -->
    <h1>欢迎进入蓝梦音乐网</h1>
    <p>这里有你想听的每一首歌。</p>
</body>
</html>
<!DOCTYPE html>必须是第一行。没有它，浏览器会切到「怪异模式」，很多 CSS 会莫名其妙不生效
<head>标题、字符集、外链 CSS、SEO 信息。这里的东西不会出现在页面上（除了 <title> 显示在标签栏）
<body>页面上你能看见的一切
charset="UTF-8"不写或者写错，中文就是一堆「锟斤拷」

第一个网页：三分钟跑起来

第 1 步新建文件夹 lanmeng，在里面新建文本文件，改名 index.html（扩展名一定要是 .html，看不到扩展名就去「查看 → 文件扩展名」打开）
第 2 步用编辑器打开（HBuilderX / VS Code / 记事本都行，课程要求用 HBuilderX），把上面那段代码敲进去
第 3 步双击 index.html，或者 HBuilderX 里按 Alt + B 在浏览器打开
第 4 步改一个字，保存，回浏览器按 F5 刷新，看变化
三个新手坑：
① 文件名是 index.html.txt——系统默认隐藏扩展名，你以为改了其实没改。
② 中文路径 / 空格路径——本地能开，传到服务器就可能 404。文件夹和文件名全部用英文小写 + 短横线。
③ 改完不保存就刷新——编辑器标签上有个小圆点，就是没保存。

HBuilderX 里要认识的四个地方

项目管理器左边，管文件。新建项目时选「基本 HTML 项目」，它会自动生成骨架
编辑区中间。输入 ! 再按 Tab，能一键生成 HTML5 骨架（Emmet 语法）
预览Alt + B，内置浏览器打开；右键可「在外部浏览器打开」
控制台浏览器里按 F12，Console 看报错、Elements 看结构、Styles 看样式从哪来——这三个面板，是你以后最常用的三个工具
自己动手：做一个「欢迎进入时空电影网」的页面。要求：标题、一句话介绍、一张图（先用占位图）、页脚写你的名字。不用 CSS，能显示出来就算过。这一步做的，就是教材单元 1 的独立训练。

02HTML 骨架与常用标签

HTML 的标签只有两类：容器（有开始有结束，里面装东西）和空元素（自己一个，没有结束标签）。记住这个分类，就不会再写出 <img></img> 这种怪东西。

标题：h1 到 h6

<h1>蓝梦音乐网</h1>
<h2>本周推荐</h2>
<h3>华语流行</h3>
是什么六级标题，数字越小越重要、字越大（浏览器默认样式）
规则一个页面只放一个 h1（相当于文章大标题），往下按层级用，别跳级（h2 下面直接 h4）
坑h1 不是「最大的字」，是「最重要的标题」。想让字大，用 CSS 改 font-size，别拿 h1 当排版工具

段落、换行、横线

<p>第一段。段落之间浏览器会自动留空隙。</p>
<p>第二段。<br>这里强制换行，但还算同一段。</p>
<hr>
<p>横线下面又是新的一段。</p>
<p>段落。块级元素，独占一行，上下有默认外边距
<br>换行。空元素。**只用在「同一段里必须断行」的地方**（地址、诗歌）
<hr>水平分割线，语义是「话题转换」。空元素
最经典的错误用法：用一堆 <br><br><br> 来拉开间距。间距是 CSS 的事（margin），<br> 是「文字换行」的事。你用三个 br 撑出来的距离，换个字号就全乱了。

图片 img

<img src="images/logo.png" alt="蓝梦音乐网标志" width="120">
<img src="../assets/banner.jpg" alt="音乐节海报">
src图片路径。相对路径 images/a.png；上一级 ../a.png；绝对路径只在同域名下可靠
alt图挂了显示的文字，也是读屏软件念的内容。必填，装饰图写 alt=""
width / height只写一个，另一个按比例自动算。两个都写死，容易压扁
格式照片用 .jpg，图标/透明背景用 .png 或 .webp，动图 .gif，矢量 .svg
路径三连坑：① 文件名大小写（Logo.png ≠ logo.png）；② 中文名（图片1.png 在服务器上经常乱码）；③ 反斜杠（HTML 里写 images\a.png 是错的，必须 /）。

特殊符号：不能直接打的字符

< 和 > 在 HTML 里有特殊含义，想显示它们本身，要用实体字符。

&lt;<&gt;>&amp;&
&nbsp;不换行空格&copy;©&reg;®
&yen;¥&times;×&mdash;—
为什么不建议用 &nbsp; 排版：它是不换行空格，连打五个就是「五个不能断开的空格」，窗口一窄整段话会溢出去。缩进用 CSS 的 text-indent，间距用 margin。

注释

<!-- 这是注释，浏览器不显示，也不会执行 -->
<!-- 可以多行
     用来标注「这块是导航」 -->

div 和 span：两个「没有含义」的盒子

<div class="nav">      <!-- 块级：独占一行，用来装一大块 -->
    <span>首页</span>   <!-- 行内：跟着文字走，用来包一小段 -->
    <span>歌单</span>
</div>
<div>块级容器，没有语义，纯粹为了布局和分组
<span>行内容器，没有语义，纯粹为了给一小段文字单独上样式
能不用 div 就别用：页眉用 <header>，导航用 <nav>，正文用 <main>，一节用 <section>，页脚用 <footer>。语义化标签和 div 长得一样，但读屏软件、搜索引擎、三个月后的你，都更看得懂。

自己动手

做「蓝梦音乐网 · 音乐节」页面的第一版：一个大标题、一张海报图、两段介绍、一条分割线、页脚。要求全部用语义标签，不用一个 <br> 排版。这就是教材单元 2 的引导训练 2-1。

03文字格式化与列表

教材把「文本格式化标签」和「列表标签」放在同一课。它们确实是一类——都是「让一段文字有结构」。区别是：前者标语气，后者标条理。

语气标签：哪些要重点，哪些是引用

<p>这首歌<strong>一定要听</strong>，<em>真的</em>。</p>
<p>原价 <del>¥99</del>，现价 <ins>¥49</ins>。</p>
<p>公式：H<sub>2</sub>O，面积：a<sup>2</sup></p>
<p><mark>这一句是重点</mark>，<small>这一句是补充</small></p>
<strong>重要。默认加粗。语义是「重要」，不是「加粗」
<em>强调语气。默认斜体。语义是「重读」
<del> / <ins>删除 / 插入。电商划线价就用 del
<sub> / <sup>下标 / 上标
<mark>高亮，默认黄底
<small>小一号的补充说明（版权、注释）
<b> / <i>只改外观，不带语义。书上会讲，实际项目里少用，能用 strong/em 就用它们
一句话：<b> 是「加粗」，<strong> 是「重要」。看上去一样，搜索引攀和读屏软件只认后者。

无序列表 ul：并列的几项

<ul>
    <li>华语流行</li>
    <li>欧美摇滚</li>
    <li>日系治愈</li>
</ul>
是什么一组并列、没有先后顺序的条目。默认前面是小圆点
规则<ul> 里面只能放 <li>，不能直接塞文字或别的标签
用在哪导航菜单（实际项目里 90% 的导航都是 ul）、商品列表、特点罗列

有序列表 ol：有先后的几步

<ol>
    <li>注册账号</li>
    <li>选择会员</li>
    <li>开始听歌</li>
</ol>

属性：start="5" 从 5 开始，reversed 倒序，type="A" 用字母。步骤、排行榜、教程都用它。

描述列表 dl：名词 + 解释

<dl>
    <dt>会员</dt>
    <dd>每月 ¥15，可无限下载</dd>
    <dt>音质</dt>
    <dd>普通用户 128kbps，会员 320kbps</dd>
</dl>

dt 是词条，dd 是解释。做「参数表」「FAQ」「术语表」比表格更合适。

嵌套：列表里还能放列表

<ul>
    <li>华语
        <ul>
            <li>流行</li>
            <li>民谣</li>
        </ul>
    </li>
    <li>欧美</li>
</ul>
嵌套的唯一规则：子列表必须写在 <li> 里面，不能写在两个 <li> 中间。写错了浏览器会自动帮你「修」——修出来的结构和你想的不一样，CSS 就对不上了。

用 CSS 改列表的样子（先看效果，第 09 节细讲）

ul { list-style: none; padding-left: 0; }     /* 去掉小圆点，导航栏必做 */
ol { list-style: decimal; }
li { margin: 6px 0; }
自己动手：给音乐节页面加一个「本周歌单」——用 <ol> 排前三名，用 <ul> 排风格分类，歌曲名用 <strong>，歌手用 <em>。这一节对应教材单元 2 的引导训练 2-2 的「列表」部分。

04图片、音频、视频

教材在单元 2 里讲了 <img>、<audio>、<video> 和 <marquee>。前三个是现在还在用的，最后一个只剩考古价值——但考试会考，所以都得知道。

img 的完整写法

<img src="images/poster.jpg"
     alt="2026 蓝梦音乐节海报"
     width="640" height="360"
     loading="lazy">
loading="lazy"懒加载，滚到才下载。一页几十张图时必加
srcset给不同屏幕准备不同尺寸的图，手机不下载大图（进阶）
图片尺寸先用图片编辑工具压到实际显示尺寸。一张 4000px 的图缩成 200px 显示，白等多几秒

音频 audio

<audio controls>
    <source src="audio/song.mp3" type="audio/mpeg">
    <source src="audio/song.ogg" type="audio/ogg">
    你的浏览器不支持音频，<a href="audio/song.mp3">点这里下载</a>
</audio>
controls显示播放条。不加就是「隐形播放器」，一般都要加
autoplay自动播放。现代浏览器默认拦截——除非静音或有用户交互
loop循环
preloadnone / metadata / auto，省流量的开关

视频 video

<video controls width="640" poster="images/cover.jpg">
    <source src="video/mv.mp4" type="video/mp4">
    你的浏览器不支持视频。
</video>

和 audio 几乎一样，多三个属性：poster（没播放时的封面图）、width/height、muted（静音，配 autoplay 才能自动播）。

格式选择：视频优先 mp4（H.264），兼容性最好；音频优先 mp3。别用 .wav 放网页——一首歌几十 MB。能用外链视频平台（B 站、腾讯视频）就外链，自己托管视频的流量费很贵。

marquee：教材有，现实里别用

<marquee direction="left" scrollamount="6" behavior="scroll">
    本店今日全场八折
</marquee>
是什么让内容滚动的老标签，IE 时代的东西
现状已废弃。浏览器还能认，但标准里删了，无障碍也差（读屏软件念不了、晕动症用户难受）
考试怎么办知道它怎么写、几个属性什么意思就行，答题时照写，做项目时别用
替代方案CSS 动画：@keyframes + transform: translateX()；系统开了「减少动态效果」时用 @media (prefers-reduced-motion) 关掉
/* 现代写法：一条无限滚动的公告 */
.notice { overflow: hidden; white-space: nowrap; }
.notice span { display: inline-block; animation: scroll 12s linear infinite; }
@keyframes scroll { from { transform: translateX(100%); } to { transform: translateX(-100%); } }

图片的三种常见摆法

等比缩放img { max-width: 100%; height: auto; }——最常用，保证不溢出容器
裁切填充img { width: 100%; height: 200px; object-fit: cover; }——卡片封面图用这个，不变形
完整显示object-fit: contain;——商品图、海报缩略图，宁可留白也不裁
自己动手：给音乐节页面加一个「试听」区块：一张封面图 + 一个 audio 播放器 + 一段视频。没有素材就先用占位图和免费音源（比如 freesound、Pixabay），别去网上随便下别人的歌。

05表格：先说数据，再说布局单元 3

表格在 HTML 里有两个身份：装数据（本职）和排版（旧社会的临时工）。教材两件事都讲，这里把它拆开：数据表格要学扎实，布局表格要知道它为什么被淘汰。

最小的一张表

<table>
    <caption>2026 年 10 月歌单播放量</caption>
    <thead>
        <tr><th>歌曲</th><th>歌手</th><th>播放量</th></tr>
    </thead>
    <tbody>
        <tr><td>晴天</td><td>周杰伦</td><td>120 万</td></tr>
        <tr><td>起风了</td><td>买辣椒也用券</td><td>98 万</td></tr>
    </tbody>
</table>
<table>整张表
<tr>一行（table row）
<td>一个格（table data）
<th>表头格，默认加粗居中。给读屏软件识别「这一列是什么」
<caption>表格标题，必须紧跟在 <table> 后面
thead / tbody / tfoot表头区 / 表体区 / 表尾区。便于样式分组，也便于打印时每页重复表头
规矩：一行里 <td> 的个数要一致（除非合并），否则表格会「缺角」。写完数一遍，是最快的自检方法。

合并单元格：colspan 与 rowspan

<table>
    <tr>
        <th colspan="2">姓名与年龄</th>   <!-- 横着占 2 格 -->
        <th>城市</th>
    </tr>
    <tr>
        <td rowspan="2">阿猫</td>          <!-- 竖着占 2 行 -->
        <td>18</td>
        <td>株洲</td>
    </tr>
    <tr>
        <!-- 这里不用再写「阿猫」那一格，它被上面占了 -->
        <td>19</td>
        <td>长沙</td>
    </tr>
</table>
colspan="2"横跨 2 列，这一行就要少写 1 个 td
rowspan="2"竖跨 2 行，下一行就要少写 1 个 td
合并单元格最经典的翻车：只加了 rowspan，忘了把下面那一行对应的 <td> 删掉——表格就整体往右错一格。检查方法：每一行的「td 个数 + 被上面占掉的格数」必须相等。

细线表格：教材的重点

默认表格是「双线 + 有间隙」的老样子。要变成细线表格，有两种写法。

<!-- 老写法（教材里有，能跑，但别在新项目里用） -->
<table border="1" cellspacing="0" cellpadding="8"> ... </table>
/* 新写法：CSS 控制 */
table {
    width: 100%;
    border-collapse: collapse;   /* 相邻边框合并成一条线，细线的关键 */
}
th, td {
    border: 1px solid #444;      /* 一条 1px 的线 */
    padding: 8px 12px;           /* 格子里的留白，代替 cellpadding */
    text-align: left;
}
th { background: #1c2740; }
tr:nth-child(even) td { background: rgba(255,255,255,.03); }  /* 隔行变色 */
border="1"HTML 属性，等于给表格加边框。表现和结构混在一起，不推荐
cellspacing格子之间的间隙，等于 CSS 的 border-spacing
cellpadding格子内边距，等于 CSS 的 padding
border-collapseseparate（默认，双线）/ collapse（合并，细线）

为什么表格不再用来布局

当年怎么用整页切成「上中下、左中右」，全部用 <table> 的格子摆
为什么不灵了① 结构臃肿，一层套一层，改一处动全身；② 代码没有语义，读屏软件念成一堆「表格」；③ 手机上根本排不开；④ 内容和样式死绑，换皮肤等于重写
现在用什么结构用 <div> + 语义标签，布局用 Flex（15 节）和 Grid（16 节）
考试怎么办教材单元 3 要求「用一张表格实现简单布局」，会做、会解释原理就行；真做项目，用 Flex
分辨口诀：装的是数据（歌单、成绩、价格）→ 用 table；装的是版块（导航、侧栏、页脚）→ 用 div + Flex/Grid。

表格的响应式（手机上别撑破屏）

.table-wrap { width: 100%; overflow-x: auto; }  /* 外层包一个，窄屏就能左右滑 */
table { min-width: 520px; }

06表单：网页唯一能「收东西」的地方单元 3

网页上 99% 的内容是「给你看」的，只有表单是「让你填」。注册、登录、搜索、下单、留言——全是表单。这一节把它拆成三层：装东西的 form、填东西的控件、送出去的方式。

第一层：form 容器

<form action="/register" method="post">
    ...
</form>
action提交到哪。空着或省略 = 提交给当前页面
methodget（默认，参数拼在网址后面，能被看到、能收藏、有长度限制）/ post（放在请求体里，适合密码、大文件）
enctype有文件上传时必须写 multipart/form-data，否则只能传过去一个文件名
novalidate关掉浏览器自带的校验（自己写 JS 校验时才用）
最重要的一句话：没有 name 属性的控件，不会被提交。后端收到的是「name = value」这样的键值对，name 是你给它起的字段名，value 是用户填的内容。少写一个 name，那个框就是白填。

第二层：input 的十几种类型

<form action="/register" method="post">
    <label for="user">用户名</label>
    <input type="text" id="user" name="username" placeholder="4-12 位字符" required>

    <label for="pwd">密码</label>
    <input type="password" id="pwd" name="password" minlength="6" required>

    <label for="mail">邮箱</label>
    <input type="email" id="mail" name="email" placeholder="name@example.com">

    <label for="phone">手机</label>
    <input type="tel" id="phone" name="phone" pattern="1[3-9]\d{9}">

    <input type="radio" id="m" name="gender" value="male" checked>
    <label for="m">男</label>
    <input type="radio" id="f" name="gender" value="female">
    <label for="f">女</label>

    <input type="checkbox" id="agree" name="agree" value="yes">
    <label for="agree">我已阅读并同意用户协议</label>

    <input type="file" name="avatar" accept="image/*">
    <input type="date" name="birthday">
    <input type="number" name="age" min="1" max="120">
    <input type="hidden" name="source" value="web">

    <button type="submit">注册</button>
    <button type="reset">重填</button>
</form>
text / password单行文本 / 密文（只是显示成点，不加密，加密靠 https）
email / tel / url带格式提示的文本框，手机上会弹对应键盘
number / range数字 / 滑块，配合 min max step
radio单选。同一组的 name 必须一样，否则每个都是独立单选，全都能选
checkbox多选。同组 name 一样时，后端收到的是数组
file文件选择，form 要配 enctype，accept 限定类型
date / time / color日期 / 时间 / 取色器，浏览器自带控件
hidden看不见但要提交的值（比如来源、订单号）
submit / reset / button提交 / 重置 / 纯按钮（不提交，留给 JS 绑事件）

第三层：下拉、多行文本、分组

<label for="city">城市</label>
<select id="city" name="city">
    <option value="">请选择</option>
    <option value="changsha">长沙</option>
    <option value="zhuzhou" selected>株洲</option>
</select>

<select name="style" multiple size="3">
    <optgroup label="华语">
        <option value="pop">流行</option>
        <option value="folk">民谣</option>
    </optgroup>
</select>

<textarea name="intro" rows="5" cols="40" placeholder="介绍一下你自己"></textarea>

<fieldset>
    <legend>账号信息</legend>
    <!-- 一组相关的控件 -->
</fieldset>
select下拉。提交的是 option 的 value，不是显示的文字——value 不写，提交的就是文字本身，中文会变乱码
multiple size多选 + 显示几行
optgroup给选项分组，只有 label，没有 value
textarea多行文本，没有 value 属性，内容写在标签中间
fieldset / legend把一组控件框起来，legend 是框上的标题

第四层：不用写 JS 就有的校验

required必填
placeholder提示文字，不是默认值，用户一打字就消失
pattern正则校验，比如手机号 1[3-9]\d{9}
minlength / maxlength长度限制
min / max / step数值范围
autocomplete让浏览器记住，on / off
但要清醒：这些校验只挡「手滑」，挡不住坏人。前端校验是体验，后端校验才是安全。用户按 F12 就能把 required 删掉。

点「提交」之后发生了什么

1浏览器检查校验，不通过就弹提示，不发请求
2把所有带 name 的控件拼成 name=value&name=value
3按 method 发出去：get 拼在网址后，post 放在请求体
4服务器返回新页面，浏览器整页跳转——这就是为什么「提交后页面刷新了」
没有后端时怎么看效果：把 method 改成 get，action 留空，提交后看地址栏——你填的东西全在问号后面，这就是「表单数据长什么样」最直观的一课。

07CSS 入门：语法、写法、谁说了算单元 4

HTML 是骨架，CSS 是皮肤。没有 CSS 的网页，就是一份 Word 文档。

一条 CSS 由三部分组成

h1 { color: #38bdf8; font-size: 32px; }
└┬┘  └──────┬──────┘
选择器        声明（属性: 值;）
选择器「谁」——挑中哪些元素
属性「改什么」——颜色、大小、位置
值「改成什么」
CSS 写错不报错。少一个分号、冒号写成中文的、选择器漏了点——浏览器不会告诉你，它只是悄悄跳过那一行。所以「样式没生效」时，第一件事不是重写，是去 F12 的 Styles 面板看这条规则在不在、有没有被划掉。

三种写法：行内、内部、外部

<!-- 1. 行内样式：直接写在标签上 -->
<h1 style="color: red;">标题</h1>

<!-- 2. 内部样式表：写在 head 里的 style 中 -->
<style>
    h1 { color: red; }
</style>

<!-- 3. 外部样式表：单独一个 .css 文件，link 进来 -->
<link rel="stylesheet" href="css/style.css">
行内优先级最高，但和结构混在一起。只在用 JS 动态改样式、或改别人的老页面时用
内部只对当前页面生效。适合单页小项目、临时调试
外部标准做法。一份样式管全站，改一处全站变；浏览器还能缓存
一句话：「一份数据，四处生效」——这句话用在 CSS 上就是：能写进外部样式表的，就别写行内。

层叠：同一条属性被写了两遍，听谁的

CSS 全称 Cascading Style Sheets，层叠就是它的第一性原理。规则按下面的顺序比，前一条赢了就不用看后一条：

1!important —— 谁写了谁赢（慎用，用了以后很难改）
2来源 —— 浏览器默认 < 用户样式 < 作者样式（就是你写的）
3优先级（权重） —— 见下表
4先后顺序 —— 权重一样，后写的赢

优先级怎么算

1000行内 style="..."
100ID 选择器 #top
10类 .nav、属性 [type="text"]、伪类 :hover
1元素 div、伪元素 ::before
0通配符 *、继承来的样式
p            { color: black; }   /* 0,0,1 */
.note p      { color: gray;  }   /* 0,1,1  ← 赢 */
#main p      { color: blue;  }   /* 1,0,1  ← 再赢 */
<p style="color:red">            /* 1,0,0,0 行内 ← 最赢 */
别背数字，记三句话：① ID 比类大，类比元素大；② 写得越「具体」越赢；③ 能不写 !important 就别写——它是最后的创可贴，不是日常药。

继承：有些属性会「传下去」

会继承color、font-*、line-height、text-align、letter-spacing、visibility
不继承margin、padding、border、background、width、height、display、position

所以在 body 上写一次 color 和 font-family，全站文字都会跟着变——这就是「全局字体」最省事的写法。

注释

/* 这是 CSS 注释，可以多行 */
/* 注意：不是 // ，也不是 <!-- --> */

08选择器大全：怎么精准挑中那个元素单元 4

选择器是 CSS 的「瞄准镜」。挑不中，样式再好也白搭。教材要求掌握 6 种，这里给全 12 种，外加优先级和命名。

基础四种

p        { }   /* 元素：所有 p 标签 */
.active  { }   /* 类：class="active" 的所有元素（最常用） */
#header  { }   /* ID：id="header" 的那一个（一页只能一个） */
h1, h2, h3 { } /* 群组：逗号，三个一起挑 */
新手第一大坑：类选择器必须带点。.nav 是「class 叫 nav 的元素」，nav 是「nav 标签」。少一个点，样式就完全没反应。这是初学者最常犯、也最容易查半天的错。

组合：后代、子、兄弟

.nav li      { }  /* 后代：.nav 里所有层级的 li（子孙都算） */
.nav > li    { }  /* 子：只算 .nav 的直接儿子 */
h2 + p       { }  /* 相邻兄弟：紧挨着 h2 的下一个 p */
h2 ~ p       { }  /* 通用兄弟：h2 后面所有同级 p */
空格 vs >空格是「里面任意层级」，> 是「里面第一层」。能用 > 就用 >，影响范围小，不容易误伤
用途导航菜单 .nav li、表单 .form > label、标题下方第一段 h2 + p（去掉上边距）

属性与伪类

input[type="text"]      { }  /* 属性选择器：type 是 text 的 input */
a[href^="http"]         { }  /* 以 http 开头 */
a[href$=".pdf"]         { }  /* 以 .pdf 结尾 */

a:hover                 { }  /* 鼠标悬停 */
li:first-child          { }  /* 第一个 */
li:last-child           { }  /* 最后一个 */
li:nth-child(2n)        { }  /* 偶数行（2n+1 是奇数） */
li:not(:last-child)     { }  /* 除了最后一个 */
input:focus             { }  /* 获得焦点 */
input:checked           { }  /* 被选中 */
input:disabled          { }  /* 禁用 */
p:empty                 { }  /* 里面什么都没有 */
两个高频用法：① 导航最后一项不要右边框：.nav li:not(:last-child) { border-right: 1px solid #333; }；② 表格隔行变色：tr:nth-child(even) { background: #0d1524; }。

伪元素：往元素里「塞」内容

.title::before {
    content: "";
    display: inline-block;
    width: 4px; height: 18px;
    background: #38bdf8;
    margin-right: 10px;
}

.clearfix::after {
    content: "";
    display: table;
    clear: both;
}
::before / ::after在元素内容前 / 后插入内容，必须写 content
能干什么装饰性小竖条、角标、清除浮动、图标、引号、水印大字
注意内容是「装饰」，别把正文塞进去——读屏软件读不到，复制也复制不走

优先级速查（配合 07 节）

写法权重
*0
li1
.nav li11
li:nth-child(2)11
#nav li101
style="..."1000
实战建议：选择器够用就行，别写太长。div.header > ul.nav > li > a 这种能写但没必要——权重高到以后想覆盖只能上 !important。一层类选择器能解决，就别堆三层。

命名：让三个月后的你看得懂

好名字.site-header、.song-card、.btn-primary、.is-active
坏名字.red（以后改成蓝色怎么办）、.div1、.a、.box2
规则小写 + 连字符；按「是什么」命名，不按「长什么样」命名；状态类统一加 is- 前缀

09美化文本：让字「好读」比「好看」重要

教材把「美化文本」和「美化图片」分成两个任务。先说文本——因为网页 80% 的内容是字，字排不好，图再漂亮也像地摊广告。

字体：font-family 要写一串

body {
    font-family: "PingFang SC", "Microsoft YaHei", "Helvetica Neue", Arial, sans-serif;
}
为什么写一串浏览器从左往右找，找到第一个装了的就用。最后一定放一个通用族名兜底
通用族sans-serif 无衬线（屏幕首选）、serif 衬线、monospace 等宽（代码）
中文字体Windows 用「微软雅黑」，Mac 用「苹方」。别用「宋体」做正文，屏幕上发虚
字体文件想用特殊字体，@font-face 引入；中文字体动辄 5-10MB，网页上慎用

字号与行高：两个必须一起调的数字

body  { font-size: 16px; line-height: 1.8; }
h1    { font-size: 2rem;  line-height: 1.3; }
.small{ font-size: 13px;  }
font-size正文 16px 起步，手机上别小于 14px（小于 14 用户要放大）
line-height写不带单位的数字（1.8），它按「自己的字号」算；写 28px 是死值，换个字号就崩
经验值正文 1.7–1.9；标题 1.2–1.4（标题行高要小，看起来才「紧」）
一句话：行高是「呼吸」。1.2 的行高像挤公交，2.2 的行高像站操场，1.8 才是正常走路。

字重、颜色、装饰

.title   { font-weight: 700; }        /* 100-900，常用 400 常规 / 700 加粗 */
.muted   { color: #93a9c9; }          /* 次要信息用低对比度 */
.hint    { color: rgba(147,169,201,.7); }
a        { color: #38bdf8; text-decoration: none; }
a:hover  { text-decoration: underline; }
del      { color: #5d6f8c; }
颜色写法#38bdf8 十六进制 / rgb(56,189,248) / rgba(56,189,248,.5) 带透明度 / hsl()
对比度正文和背景的对比度至少 4.5:1。浅灰字 + 白底 = 看不清，这是年轻设计师最常犯的错
链接去掉下划线可以，但一定要有颜色区分，否则用户不知道哪里能点

排版：对齐、缩进、间距

p {
    text-align: justify;      /* 两端对齐，中文段落首选 */
    text-indent: 2em;         /* 首行缩进两个字 */
    letter-spacing: 0.5px;    /* 字间距，中文适当加一点更透气 */
    margin: 0 0 1em;          /* 段落之间用 margin，不用 <br> */
}
text-alignleft / right / center / justify（两端对齐，中文排版开关）
text-indent首行缩进。2em = 两个字宽，比敲空格规范
行宽中文一行 35–45 个字最好读。太宽，眼睛换行会串行
text-wrap: pretty新的换行优化，减少「最后一行只剩一个字」。只管孤字，不管断词

阴影与描边

h1 { text-shadow: 0 2px 12px rgba(56,189,248,.35); }
.title { -webkit-text-stroke: 1px rgba(255,255,255,.2); }  /* 描边字，慎用 */
三个「别」：① 别用 <br><br> 控段落间距；② 别用 &nbsp; 做缩进；③ 别在一段里塞三种字号三种颜色——层级靠「大小」和「灰度」，不靠「彩虹」。

自己动手

给音乐节页面的正文定一套排版：字体栈、16px 字号、1.8 行高、两端对齐、首行缩进 2em、段距 1em；标题用 1.3 行高。验收标准：把窗口拉窄拉宽，字始终好读，没有一行长得离谱。

10美化图片与背景：卡片感是怎么来的

「好看」的网页，八成来自三件事：圆角、阴影、留白。这一节把它们全讲完，顺便把背景和渐变一次说清。

尺寸与不变形

img {
    max-width: 100%;      /* 不撑破容器 */
    height: auto;         /* 保持比例 */
    display: block;       /* 去掉图片底部的神秘 4px 缝隙 */
}

.cover {
    width: 100%;
    height: 200px;
    object-fit: cover;    /* 裁切填满，不变形 */
    object-position: center 30%;  /* 裁的时候保哪里 */
}
那个 4px 缝隙：图片默认是「行内元素」，和文字一样按基线对齐，下面会留一条基线空隙。display: block 一行解决。这个坑几乎每个人都踩过一次。

圆角、阴影：卡片的两件套

.card {
    border-radius: 16px;
    box-shadow: 0 12px 30px rgba(2, 6, 15, .45);
    border: 1px solid rgba(96, 165, 250, .2);
    overflow: hidden;          /* 让子元素（比如图片）跟着圆角裁 */
}

.avatar {
    width: 72px; height: 72px;
    border-radius: 50%;        /* 正圆 */
    object-fit: cover;
}
border-radius四个角可以分开写：16px 16px 0 0（只有上半圆角，卡片顶部用）
box-shadow水平偏移 垂直偏移 模糊 颜色。阴影颜色用深色透明，别用纯黑
层次感阴影别太黑太重。真实世界的光是「柔」的——大模糊、低透明度，最像真的

背景：background 五个属性

.hero {
    background-color: #070c17;
    background-image: url("images/banner.jpg");
    background-repeat: no-repeat;
    background-position: center;
    background-size: cover;
}
/* 简写，顺序随意，但 size 要跟 position 用 / 隔开 */
.hero { background: #070c17 url("images/banner.jpg") center / cover no-repeat; }
background-sizecover 填满（可能裁）/ contain 完整显示（可能留白）/ 100% auto
background-attachmentfixed 做「视差」效果，移动端有兼容问题，慎用
多重背景逗号隔开，先写的在上面：background: url(a.png), url(b.png);

渐变：不找图也能做出高级感

.btn {
    background: linear-gradient(135deg, #38bdf8, #6366f1);
}
.overlay {
    background: linear-gradient(to top, rgba(7,12,23,.95), rgba(7,12,23,0) 60%);
}
linear-gradient角度 + 颜色节点。135deg 是左上到右下
radial-gradient从中心往外散，做「光晕」最像
遮罩用法图片上压一层「从黑到透明」的渐变，文字就压得住——首屏大图配标题的标准做法

交互：hover 的一点点变化

.card {
    transition: transform .25s ease, box-shadow .25s ease, border-color .25s ease;
}
.card:hover {
    transform: translateY(-4px);
    border-color: #38bdf8;
    box-shadow: 0 18px 40px rgba(2,6,15,.55);
}
img:hover { filter: brightness(1.08) saturate(1.1); }
克制的原则：动效是「提示这块能点」，不是「看我多会动」。位移不超过 6px、时长 200–300ms，就够了。另外记得尊重系统设置：@media (prefers-reduced-motion: reduce) { * { transition: none; } }

自己动手

做一张「歌单卡片」：封面图（object-fit cover）+ 圆角 + 阴影 + 悬停上浮 + 歌名/歌手两级文字。做三个一样的卡片，用 Grid 排一行。这张卡片，就是整个音乐网首页的积木。

11盒子模型：所有布局的地基单元 5

浏览器眼里，页面上每一个元素都是一个矩形盒子。盒子有四个圈，从里到外：内容 → 内边距 → 边框 → 外边距。

四层结构

┌─────────────────────────────┐  ← margin（外边距，盒子外面的空气）
│  ┌───────────────────────┐  │  ← border（边框）
│  │  ┌─────────────────┐  │  │  ← padding（内边距，内容和边框之间的空气）
│  │  │    content      │  │  │
│  │  └─────────────────┘  │  │
│  └───────────────────────┘  │
└─────────────────────────────┘
.box {
    width: 300px;
    padding: 20px;
    border: 2px solid #38bdf8;
    margin: 16px;
}
实际占多宽默认（content-box）：300 + 20×2 + 2×2 = 344px，再加 margin 16×2 = 376px
这就是「明明写了 300px，怎么把版面撑破了」的原因padding 和 border 是往外加的

box-sizing：一行救全站

*, *::before, *::after { box-sizing: border-box; }

加上这一行之后，width: 300px 就是「连 padding 和 border 一起算，总宽 300」。你做响应式、算百分比、写 Grid 的时候，再也不用减来减去。

直接抄走：现在几乎所有项目的第一行 CSS 都是它。教材里可能没强调，但不写这一行，你会多花一倍时间调宽度。

margin 的两个怪脾气

上下相邻两个盒子的上下 margin 不会相加，取大的那个（20 和 30 相邻，间距是 30，不是 50）
父子塌陷子元素的 margin-top 会「穿透」父元素，跑到父元素外面去——父元素跟着往下掉
/* 三种解法，任选其一 */
.parent { padding-top: 1px; }        /* 给父元素一点内边距 */
.parent { overflow: hidden; }        /* 触发 BFC */
.parent { display: flow-root; }      /* 最干净，专门为这个发明的 */
负 margin 能用吗？能，常用来让元素「贴边溢出」或修正 1px 缝隙。但它是双刃剑——新手先别用，能用 padding/transform 解决的，就别用负 margin。

溢出：内容比盒子大怎么办

.box { overflow: hidden; }   /* 超出部分裁掉（也常用来清浮动、做圆角裁切） */
.box { overflow: auto; }     /* 需要时出滚动条，最常用 */
.box { overflow: scroll; }   /* 永远有滚动条 */
.box { overflow-x: auto; white-space: nowrap; }  /* 只横向滚动，做标签栏 */

居中：盒子模型的第一个实战

/* 1. 块级元素水平居中 */
.box { width: 600px; margin: 0 auto; }

/* 2. 文字水平居中 */
.title { text-align: center; }

/* 3. 一个盒子在页面正中（老办法，现在用 Flex 更省事） */
.center { position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%); }

/* 4. 一个盒子在页面正中（现代办法） */
body { display: grid; place-items: center; min-height: 100vh; }

百分比参照谁

width: 50%父元素内容宽度的 50%
padding: 10%父元素宽度的 10%（上下 padding 也按宽度算，这是个老坑）
height: 100%父元素高度——父元素没写高度时，它等于 auto，100% 就失效
margin: auto左右 auto 才居中；上下 auto 在普通文档流里不居中
自己动手：做一个「三栏卡片」：每张卡片 300px 宽、内边距 20px、边框 1px、外边距 16px。先不加 box-sizing，量一下实际宽度；再加上，再量一次。亲眼看见差别，比背十遍定义管用。

12文档流与 display：元素怎么排队

不写任何 CSS 的时候，页面也有布局——它叫标准文档流：块级元素从上往下摞，行内元素从左往右排。所有布局技巧，本质都是「打破这个默认排队」。

三种显示类型

块级 blockdiv p h1 ul li table form header section独占一行；宽高、上下 margin 都有效；不写宽度时默认撑满父元素
行内 inlinespan a strong em img input label跟文字排队；width/height 无效；上下 margin 无效，只有左右有效
行内块 inline-block用 display 手动改像文字一样排队，但能设宽高——按钮、标签、小图标用得多
span { width: 200px; }           /* 无效！行内元素不认宽 */
span { display: inline-block; width: 200px; }  /* 有效 */

div { display: inline; }         /* 块变行内，宽高失效 */
a   { display: block; }          /* 行内变块，能撑满整行，做导航最常用 */
li  { display: inline-block; }   /* 横排菜单的经典写法 */
为什么导航链接常写 display: block：链接是行内的，只有文字区域能点。改成块级后，整个格子都能点，鼠标手感立刻不一样。这是「可用性」而不是「好看」的改动。

行内元素的两个坑

/* 坑 1：inline-block 之间有看不见的空白 */
<li></li><li></li>   /* 换行写就有 4px 缝隙 */
ul { font-size: 0; }      /* 父元素字号归零，再给 li 设回字号 */
li { display: inline-block; font-size: 16px; }

/* 坑 2：行内元素按基线对齐 */
img { vertical-align: middle; }   /* 或者 display: block */

隐藏一个元素的三种方式

display: none彻底消失，不占位置，读屏也读不到。做标签页切换、弹窗默认隐藏
visibility: hidden看不见，但还占着位置。做「占位不跳版」的隐藏
opacity: 0透明，还占位置，还能点。做淡入淡出动画
要「淡出且不占位」：transition 配 visibility，或者动画结束后再加 display: none。单用 opacity 做不到「消失」，它只是「看不见」。

垂直居中：这个问题的半部历史

/* 单行文字：行高等于高度 */
.btn { height: 44px; line-height: 44px; }

/* 行内块 / 图片：vertical-align */
.box { height: 200px; line-height: 200px; }  /* 父元素设行高 */
.box img { vertical-align: middle; }

/* 现代：Flex，直接说人话 */
.box { display: flex; align-items: center; justify-content: center; }

块级 vs 行内：一张判断表

要独占一行、能设宽高用块级（div / 语义标签）
要跟文字排在一起、能设宽高inline-block
只是包一小段文字上色span（行内）
要横排一堆等宽块别用 inline-block，用 Flex
自己动手：用 inline-block 排一个横向导航，量一下两个 li 之间的缝隙；再用父元素 font-size: 0 解决它。然后全部换成 display: flex，对比代码量——你会明白 15 节为什么存在。

13浮动与清除浮动：一个时代的遗产单元 5

教材单元 5 的核心就是「DIV+CSS + 盒子模型 + 浮动」。这套东西统治了网页布局十几年，考试必考、老项目必见，但新项目已经基本不用。所以这一节要学两个东西：它怎么用，和它为什么退场。

float 是干什么的

它本来是为「文字环绕图片」设计的——像杂志里图片旁边绕着文字。后来被人拿来排版，一用就是十几年。

img.left { float: left; margin: 0 16px 12px 0; }
<img class="left" src="cover.jpg" alt="">
<p>这一段文字会自动绕着图片排……</p>
.col-left  { float: left;  width: 220px; }
.col-right { float: right; width: 220px; }
.main      { margin: 0 240px; }   /* 中间栏用 margin 让位 */
float: left / right元素靠左 / 靠右，脱离标准文档流，后面的行内内容会绕开它
float: none默认值，不浮动
代价父元素「看不见」浮动的孩子，高度变成 0——这就是「高度塌陷」

高度塌陷长什么样

<div class="wrapper">
    <div class="box">我浮动了</div>
</div>
<div class="next">我会盖上去</div>

结果：.wrapper 高度是 0，.next 直接叠到浮动元素下面，版面全乱。这不是 bug，是浮动脱离文档流的必然结果。

三种清除方法

/* 1. 额外标签法（最老，最不推荐：多了一个没意义的 div） */
<div style="clear: both;"></div>

/* 2. 父元素 overflow: hidden（最简单，但会裁掉溢出内容） */
.wrapper { overflow: hidden; }

/* 3. clearfix：伪元素，最经典 */
.clearfix::after {
    content: "";
    display: table;
    clear: both;
}
.clearfix { zoom: 1; }   /* 兼容 IE6/7 的老写法，现在可以不要 */
clear: left / right / both「我这一侧不许有浮动元素」——把元素推到所有浮动元素下面
overflow: hidden触发 BFC（块级格式化上下文），父元素会包住浮动子元素
display: flow-root专门为「包住浮动」发明的新值，干净、没有副作用，现代首选

为什么今天不用浮动了

浮动的痛点要清浮动、要算宽度、要处理高度塌陷、垂直居中几乎没法做、顺序调整要改 HTML
Flex 怎么解决一行 display: flex，横排自动、等高自动、居中一行属性、顺序用 order 改
结论新项目用 Flex/Grid；浮动用来看懂老代码、应付考试、做文字环绕

用浮动搭一个两栏（教材里的样子）

<div class="layout clearfix">
    <aside class="sidebar">侧栏</aside>
    <main class="content">正文</main>
</div>

.layout  { width: 1000px; margin: 0 auto; }
.sidebar { float: left;  width: 240px; }
.content { float: right; width: 740px; }   /* 240 + 740 + 间隙 = 1000 */
算宽度是这个时代最烦的事：两栏宽度 + 间距必须刚好等于父容器，多 1px 就掉行。这也是为什么后来大家改用百分比和 Flex ——不能让「人肉加法」决定版面能不能站住。

自己动手

用浮动把音乐网首页拆成「左导航 240px + 右内容自适应」，然后故意不给父元素清浮动，看页面塌成什么样；再分别用 overflow: hidden、flow-root、clearfix 修好。这个对比，比看十遍定义都值。

14定位与 z-index：谁在上面，谁钉在屏幕上单元 6

浮动解决「横着排」，定位解决「脱离排队，放到任意位置」。导航跟着滚、按钮贴右下角、图片上压个角标、弹窗盖住全屏——全是定位。

五个 position 值

static默认。老老实实排队，top/left 写了也没用
relative相对自己原来的位置偏移，原来的位置还占着（别人不会补上来）
absolute相对最近一个「定位过的」祖先偏移，完全脱离文档流，不占位置
fixed相对浏览器窗口偏移，滚动时不动。固定导航、回到顶部按钮
sticky滚到某个位置前是 relative，之后变成 fixed。吸顶目录、吸底结算栏
.badge {
    position: absolute;
    top: 8px; right: 8px;      /* 相对最近定位祖先的右上角 */
}
.card { position: relative; }  /* 给卡片一个「定位参照」，badge 才不会跑出页面 */

.topbar { position: fixed; top: 0; left: 0; right: 0; z-index: 100; }
body    { padding-top: 64px; }  /* 固定导航会盖住内容，要给 body 让位 */

.sticky-title { position: sticky; top: 0; }  /* 滚到顶就吸住 */
absolute 的第一坑：它找的是「最近一个 position 不是 static 的祖先」。如果所有祖先都没定位，它就相对整个页面定位——所以你明明想放卡片右上角，它跑到了网页右上角。解法：给父元素加 position: relative。

z-index：谁盖住谁

.modal   { position: fixed; z-index: 1000; }   /* 弹窗 */
.mask    { position: fixed; z-index: 999;  }   /* 遮罩 */
.nav     { position: fixed; z-index: 100;  }   /* 导航 */
生效前提只对定位元素生效（position 不是 static），或者 flex/grid 的子项
数值数字大的在上。同值时，后写的在上
层级表别写 9999、99999——定一张表：内容 1、悬浮按钮 100、导航 500、遮罩 900、弹窗 1000
堆叠上下文父元素有 transform、opacity < 1、filter 时，会新建一层——子元素 z-index 再大也跳不出这层。这是「z-index 明明很大却不生效」的头号原因

四个真实场景

/* 1. 图片角标 */
.card { position: relative; }
.card .tag { position: absolute; left: 0; top: 0; background: #38bdf8; color: #04121f; padding: 2px 10px; border-radius: 0 0 10px 0; }

/* 2. 回到顶部 */
.to-top { position: fixed; right: 24px; bottom: 24px; width: 44px; height: 44px; border-radius: 50%; }

/* 3. 弹窗遮罩 */
.mask { position: fixed; inset: 0; background: rgba(0,0,0,.6); display: flex; align-items: center; justify-content: center; }
/* inset: 0 等于 top/right/bottom/left 全 0，新的简写 */

/* 4. 轮播的左右箭头 */
.slider { position: relative; }
.slider .prev, .slider .next { position: absolute; top: 50%; transform: translateY(-50%); }
.slider .prev { left: 12px; }
.slider .next { right: 12px; }

居中三件套（定位版）

/* 老方法：translate 补偿自身一半宽高 */
.center { position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%); }

/* 新方法：inset + margin auto */
.center { position: absolute; inset: 0; margin: auto; width: 300px; height: 200px; }
自己动手：给音乐网首页加三样东西——固定顶部导航（滚动不消失）、卡片右上角「HOT」角标、右下角回到顶部按钮。三个东西，三种定位，一次全练到。这就是教材单元 6 的开场。

15Flex 布局：一行代码换一个时代

2017 年之后，前端布局基本只剩两件事：一维用 Flex，二维用 Grid。教材成书时还在讲浮动，但你现在做的每一个项目，都应该用 Flex 起手。

它是什么

.box { display: flex; }   /* 父元素写上这一行，孩子自动横排 */

写完之后，这个盒子变成「弹性容器」，它的直接子元素变成「弹性项目」。容器里出现一根看不见的主轴（默认从左到右），所有项目沿着主轴排。

容器的六个属性

.box {
    display: flex;
    flex-direction: row;          /* 主轴方向：row 横 / column 竖 */
    flex-wrap: wrap;              /* 放不下时换行（默认 nowrap 硬挤） */
    justify-content: space-between; /* 主轴对齐：靠边分 */
    align-items: center;          /* 交叉轴对齐：垂直居中 */
    align-content: center;        /* 多行时的行间对齐（wrap 后才有效） */
    gap: 16px;                    /* 项目间距，替代一堆 margin */
}
justify-contentflex-start 靠头 / center / flex-end 靠尾 / space-between 两端（衔接导航）/ space-around / space-evenly
align-itemsstretch 默认拉满 / center 居中 / flex-start / flex-end / baseline 文字基线对齐
gap告别「最后一个孩子不要 margin-right」，一个 gap 全解决

项目的三个属性

.item { flex: 1; }              /* 简写：占满剩余空间，等分 */
.item { flex: 1 1 200px; }      /* 长 1 · 缩 1 · 基础 200px */
.item { align-self: flex-end; } /* 单个项目单独对齐 */
.item { order: 2; }             /* 改变显示顺序，不改 HTML */
flex-grow剩余空间怎么分，0 = 不参与
flex-shrink空间不够时缩不缩，0 = 不许缩
flex-basis基准宽度，写 auto 就看 width

五种立刻能用的写法

/* 1. 导航：logo 靠左，菜单靠右 */
.nav { display: flex; justify-content: space-between; align-items: center; }

/* 2. 完美居中（等价于「怎么这么难」的那三十年） */
.center { display: flex; justify-content: center; align-items: center; min-height: 100vh; }

/* 3. 三栏等高 */
.layout { display: flex; }
.layout > * { flex: 1; }

/* 4. 卡片底部按钮对齐（不用量高度） */
.card { display: flex; flex-direction: column; }
.card .btn { margin-top: auto; }   /* 自动吃掉剩余空间 */

/* 5. 标签栏换行 */
.tags { display: flex; flex-wrap: wrap; gap: 8px; }

两个必踩的坑

/* 坑 1：文字太长把项目撑破 → 加 min-width: 0 */
.item { flex: 1; min-width: 0; }
.item .name { overflow: hidden; text-overflow: ellipsis; white-space: nowrap; }

/* 坑 2：flex-basis 和 width 打架 → 记住 basis 优先 */
.child { flex-basis: 200px; width: 100px; }  /* 实际按 200px */
为什么要 min-width: 0：Flex 项目的默认最小宽度是「内容宽度」，文字不换行时它宁可撑破也不缩。加了 0，它才肯配合缩到容器里——这是省略号不生效的头号原因。

自己动手

把音乐网首页做成：固定导航（logo + 菜单两端对齐）、首屏垂直居中、三张歌单卡片等宽、每张卡片底部按钮对齐。全程不许用 float，不许写死高度。

16Grid 布局：二维棋盘

Flex 只管一根轴，Grid 能同时管行和列——先画格子，再往里放东西。做整页布局、卡片墙，它比 Flex 还省事。

三行代码，一个响应式卡片墙

.grid {
    display: grid;
    grid-template-columns: repeat(auto-fit, minmax(260px, 1fr));
    gap: 20px;
}
repeat(auto-fit, ...)「能放几列放几列」，自动算
minmax(260px, 1fr)每列最窄 260px，最宽平分剩余
结果宽屏 4 列，平板 2 列，手机 1 列——不用写一行媒体查询
对比一下：同样的效果用浮动要写 @media 三个断点、算宽度、清浮动。这一行，就是「工具选错了，活该加班」。

17响应式与移动端：一套代码，两种屏幕单元 7

教材叫「制作移动网页」。今天的做法不是「再做一个手机版」，而是同一份 HTML，靠 CSS 自动适配。这一节是整门课最值钱的一节——手机流量早就是大头了。

第一件事：viewport

<meta name="viewport" content="width=device-width, initial-scale=1">

没有这一行，手机会假装自己有 980px 宽，然后把整页缩小塞进屏幕——字小到看不清。这一行是所有移动端适配的前提，缺了它，后面全白写。

width=device-width页面宽度 = 设备宽度
initial-scale=1初始不放大不缩小
别加 user-scalable=no禁止缩放，对老人和视力不好的人很不友好，很多审查会直接扣分

媒体查询：到某个宽度就换一套样式

/* 移动优先：默认样式写手机，屏幕变大再增强 */
.card { padding: 16px; }

@media (min-width: 768px) {
    .card { padding: 24px; }
}

@media (min-width: 1024px) {
    .layout { display: grid; grid-template-columns: 240px 1fr; }
}
语法@media (条件) { 规则 }，条件可以是宽度、方向、分辨率、是否支持某特性
min-width vs max-widthmin-width 是「大于等于」，配移动优先；max-width 是「小于等于」，配桌面优先。别混着写，容易互相覆盖
断点选哪几个别看设备，看内容什么时候挤坏。常用 480 / 768 / 1024 / 1280

常见断点表

< 480px手机竖屏：单列、字号 15–16px、按钮铺满
480–768px手机横屏 / 小平板：两列
768–1024px平板：侧栏收起或变窄
> 1024px桌面：完整布局

单位：px、em、rem、vw

px绝对像素。简单直接，但用户改浏览器字号时不跟随
em相对父元素字号。嵌套时会层层相乘，容易失控
rem相对根元素（html）字号。全站一个基准，推荐做字号和间距
%相对父元素。流式布局的基础
vw / vh视口宽 / 高的 1%。100vh 做满屏首屏
html { font-size: 16px; }      /* 1rem = 16px */
h1   { font-size: 2rem; }      /* 32px */
.box { padding: 1.5rem; }      /* 24px */

/* 字号随屏幕流动，不用媒体查询 */
h1 { font-size: clamp(1.6rem, 4vw, 2.6rem); }
clamp(最小, 理想, 最大) 是响应式字号最省事的写法：小屏不塌、大屏不炸。教材里没有，但现在的项目里到处都是。

流式布局：让宽度自己伸缩

.wrap { width: 100%; max-width: 1100px; margin: 0 auto; padding: 0 20px; }
.col  { width: 50%; }                 /* 两栏 */
img   { max-width: 100%; height: auto; }

max-width 是响应式的灵魂：「最多这么宽，屏幕小了就跟着缩」。比写死 width: 1100px 稳得多。

手机上必须处理的六件事

1. 点击区域按钮最小 44×44px，手指没那么准
2. 输入框字号小于 16px，iOS 会自动放大页面，很烦
3. hover手机没有 hover，别把关键功能藏在 hover 里。用 @media (hover: hover) 包起来
4. 横向滚动检查是不是有元素超出屏幕——给 body 加 overflow-x: hidden 是遮丑，不是解决
5. 1px 边框高清屏上 1px 会变粗，可用 transform: scaleY(.5) 或直接接受
6. 图片手机流量贵，srcset + 压缩，别把 2MB 的图塞给手机

媒体查询写在哪

/* 方式一：集中写在 CSS 末尾 */
/* 方式二：跟在各自模块后面（推荐，改起来方便） */

.nav { display: flex; }
@media (max-width: 768px) {
    .nav { flex-direction: column; }
}

18框架与 iframe：一个已死，一个还在用单元 8

教材讲「框架」，指的是 <frameset>——把浏览器窗口切成几块，每块装一个页面。这个技术在 HTML5 里已经被删了。但教材还讲，考试还考，而且它留下的「后台管理系统布局」需求，今天还在。

frameset 长什么样（了解即可）

<!-- HTML4 的老写法，HTML5 已废弃，现代浏览器仍兼容 -->
<frameset cols="200px, *">
    <frame src="menu.html" name="menu">
    <frame src="main.html" name="main">
</frameset>
frameset替代 body，整个页面就是它
cols / rows左右切 / 上下切
frame每一格里装的页面
为什么被删网址不变（不能分享、不能收藏）、SEO 不友好、打印和手机上一团糟、无障碍差、<body> 都写不了

iframe：内联框架，还活着

<iframe src="https://player.bilibili.com/player.html?bvid=BV1xx411c7mD"
        width="640" height="360"
        title="视频播放器"
        loading="lazy"
        allowfullscreen></iframe>
现代用途嵌视频（B 站/腾讯）、嵌地图（高德/百度）、嵌支付、嵌第三方客服、后台里加载子页面
sandbox权限白名单，嵌别人的页面一定要加，防止它执行脚本、弹窗、跳转
loading="lazy"滚到才加载，省流量
安全跨域 iframe 之间不能直接读对方 DOM。要通信得用 postMessage；对方不设 X-Frame-Options 才能被嵌

后台管理系统的布局（教材那个训练的现代做法）

<div class="admin">
    <header class="topbar">蓝梦音乐网 · 后台</header>
    <aside class="side">菜单</aside>
    <main class="work">内容区</main>
</div>

.admin {
    display: grid;
    grid-template-columns: 220px 1fr;
    grid-template-rows: 56px 1fr;
    grid-template-areas:
        "top top"
        "side work";
    height: 100vh;
}
.topbar { grid-area: top; }
.side   { grid-area: side; overflow-y: auto; }
.work   { grid-area: work; overflow: auto; }

对比一下：用 frameset 做，切出来的每一块都是独立页面，点菜单要 target="main"；用 Grid 做，切换内容只是换 main 里的 HTML——网址能变、能前进后退、能做单页应用。这就是取代它的原因。

什么时候真的该用 iframe

该用内容来自别人的网站、且你不需要控制它（视频、地图、第三方表单）
不该用自己的页面之间切换、整站布局、为了「省事」把页面拆开
考试提示：教材里的 frameset 写法要会（rows、cols、frame、target、noresize、scrolling），答题时按书上写；但项目里请用 Grid，阅卷老师看到现代写法只会加分。

轮播：完整实现

<div class="slider">
    <div class="slides" id="slides">
        <img src="images/1.jpg" alt="">
        <img src="images/2.jpg" alt="">
        <img src="images/3.jpg" alt="">
    </div>
    <button class="prev">‹</button>
    <button class="next">›</button>
    <div class="dots" id="dots"></div>
</div>
/* 样式：一条横向长条，超出裁掉 */
.slider { position: relative; overflow: hidden; border-radius: 14px; }
.slides { display: flex; transition: transform .45s ease; }
.slides img { flex: 0 0 100%; width: 100%; height: 380px; object-fit: cover; }
.prev, .next { position: absolute; top: 50%; transform: translateY(-50%); width: 40px; height: 40px; border: 0; border-radius: 50%; background: rgba(0,0,0,.45); color: #fff; font-size: 22px; cursor: pointer; }
.prev { left: 12px; } .next { right: 12px; }
// 逻辑：核心只有一句——改 transform，把长条整体左移
const slides = document.getElementById("slides");
const total  = slides.children.length;
let index = 0;

function go(i) {
    index = (i + total) % total;           // 越界就绕回来（循环轮播）
    slides.style.transform = "translateX(" + (-index * 100) + "%)";
}

document.querySelector(".next").addEventListener("click", function () { go(index + 1); });
document.querySelector(".prev").addEventListener("click", function () { go(index - 1); });

加上自动播放和指示点

let timer = setInterval(function () { go(index + 1); }, 3000);

// 鼠标移上去暂停（体验细节，考试不考但很加分）
const slider = document.querySelector(".slider");
slider.addEventListener("mouseenter", function () { clearInterval(timer); });
slider.addEventListener("mouseleave", function () {
    timer = setInterval(function () { go(index + 1); }, 3000);
});

// 指示点：生成 + 高亮
const dots = document.getElementById("dots");
for (let i = 0; i < total; i++) {
    const d = document.createElement("span");
    d.className = "dot";
    d.addEventListener("click", function () { go(i); });
    dots.appendChild(d);
}
function refreshDots() {
    document.querySelectorAll(".dot").forEach(function (d, i) {
        d.classList.toggle("active", i === index);
    });
}
把 refreshDots() 放进 go() 里——每次切换都刷新指示点。这是新手最容易忘的一步：轮播动了，小圆点不动。

三个坑

变量提升循环里用 var 绑事件，点哪个都是最后一个。改成 let
定时器不清来回切页面，定时器越积越多，轮播越转越快。切走时 clearInterval
报错看不见按钮没反应，先按 F12 看 Console 的红字——浏览器早就把错误和行号写在那里了
什么时候不用 JS：只是「渐显、位移、变色」这类纯视觉变化，用 CSS 的 transition 和 @keyframes，性能更好、代码更少。JS 只管「什么时候变」，「怎么变」交给 CSS。

自己动手

给首页做轮播：三张图、左右按钮、自动播放、指示点、鼠标悬停暂停。先做「点一下换一张」，再做自动播放，最后加指示点——一次只加一个功能，坏了好找。这是教材单元 6 的引导训练。

三、二十个坑（每个都有人踩过）

1类选择器忘了点：nav {} 找的是标签，.nav {} 才是类
2CSS 写错不报错，只是不生效——去 F12 的 Styles 看
3href 少了 #：#story 是本页跳，story 是找文件
4行内元素设 width 无效，要加 display: inline-block/block
5图片底下莫名 4px，display: block 解决
6padding 把盒子撑大——加 box-sizing: border-box
7margin 上下塌陷，父子兄弟都中招
8浮动父元素高度 0——flow-root / clearfix
9absolute 找不到祖先，跑到页面角上——父元素加 position: relative
10z-index 失效——父元素有 transform/opacity，或者没设定位
11Flex 里省略号不生效——min-width: 0
12高度 100% 失效——父元素没写高度
13表单控件没 name，提交是空的
14radio 不同 name，变成各自独立
15label 没关联 for/id，点文字选不上
16中文/大写文件名，上线 404
17<br><br> 控间距，换字号就崩
18&nbsp; 做缩进，窄屏溢出
19媒体查询 max 和 min 混写，互相覆盖
20定时器没清，越跑越快

四、考试怎么对应

笔试（60%）概念（网页/网站/万维网/因特网）、标签作用、属性含义、选择器优先级、盒子模型计算、浮动与定位的区别、响应式原理
机试（40%）给一个页面效果图 / 文字描述，限时做出来：结构 + 样式 + 一个小交互。评分看还原度、代码规范、能不能跑
平时（40%）考勤、课堂表现、随堂作业——这一块最容易丢分，也最容易拿满

五、复习顺序（三天足够）

第 1 天把这 22 节从头到尾读一遍，只读不写，建立地图
第 2 天合上书，默写：HTML 骨架、三种 CSS 引入、盒子模型四层、Flex 五个属性、媒体查询语法
第 3 天不看任何代码，从零做一个「个人主页」：导航 + 首屏 + 三张卡片 + 一个表单 + 手机适配
最后一句话：这门课真正教你的不是标签，是「把一句话描述，翻译成浏览器看得懂的结构和样式」。这个能力，换成 Vue、换成 React、换成小程序，都还在用。

22结语：写给这门课结束之后的你

学完这门课，你能做出一个像样的静态网站。但更重要的是，你知道了网页是可以被「拆开看」的——任何你喜欢的网站，按 F12，它的结构、样式、甚至动效的写法，都摊在你面前。

这就是前端最迷人的地方：整个互联网都是你的教材。

接下来可以走JavaScript 深入 → Vue/React → 小程序；或者 CSS 动画、可视化；或者干脆做设计
可以回来看你这个「时空电影网」，三个月后再打开，会挑出一堆毛病——那说明你进步了
别做的事别停在「能跑就行」。同样一个页面，写十遍和写一遍的人，差的是审美和手感
一句题外话：这门课的教材是 2020 年编的，里面有些写法（frameset、marquee、表格布局）今天已经不用了。你不用纠结「书上为什么这么写」——书里是那个时代的标准答案，这里补上现在通行的写法。两个都知道，你就比只会一个的人多一层判断。
