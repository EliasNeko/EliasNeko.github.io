Anaconda：把 Python 的环境装进一个盒子

装个库为什么会打架？虚拟环境是什么？conda 和 pip 有什么区别？一次讲清。

10 节难度 低更新 2026-10-23

01它是什么

Anaconda 不是一门语言，是一个「Python + 常用科学计算包 + 环境管理」的合集。装了它，numpy、pandas、jupyter 这些不用一个个折腾。

它真正的价值是 conda：让你在同一个电脑上装好几个互不干扰的 Python 环境。

适合谁：被「装个包把另一个项目搞崩」折磨过的人。

02装哪个

  • Anaconda：完整版，3GB 左右，什么都有
  • Miniconda：只装 conda + Python，几百 MB，缺什么自己装

现在更推荐 Miniconda，干净、装得快。装完开新终端：

conda --version
conda env list
坑：Windows 安装时不要勾「Add to PATH」（官方建议），装完用「Anaconda Prompt」打开终端，否则容易和系统自带 Python 打架。

03conda 常用命令

conda create -n study python=3.11
conda activate study
conda install numpy pandas
conda list
conda deactivate
conda remove -n study --all

记住四条就够日常用：建环境、进环境、装包、退环境。

坑：每次开新终端默认在 base 环境，装包前先 conda activate 你的环境，不然全装到 base 里。

04为什么要环境

项目 A 要 numpy 1.20，项目 B 要 numpy 2.0。装在一个 Python 里，只能留一个版本，另一个项目就崩。

环境就是「每个项目一个独立的 Python 和包目录」。切环境，等于换了一整套依赖。

坑：环境建在哪个盘要注意——默认在 C 盘用户目录，装多了很占空间。可以在 .condarc 里改 envs_dirs。

05pip 和 conda 的区别

  • pip：Python 官方的包管理器，只装 Python 包，从 PyPI 下
  • conda：跨语言，能装 Python 包，也能装编译器、CUDA 这类「非 Python」的东西

同一个环境里混用没问题，但建议：能用 conda 就 conda，conda 没有再用 pip，减少依赖冲突。

坑：用 pip 装完，conda 不一定知道；conda list 可能不显示。查包用 pip list 对照着看。

06依赖冲突怎么解

报 Solving environment: failed 时，先别急着卸了重装，按顺序试：

  1. 换个源：conda config --add channels conda-forge
  2. 指定版本：conda install numpy=1.26
  3. 实在不行，新建一个干净环境，只装这次要用的
坑：在 base 环境里反复装、卸，是最容易把环境搞坏的做法。给每个项目单开环境，坏了直接删。

07Jupyter

conda activate study
conda install jupyter
jupyter notebook

浏览器会打开一个页面，能一格一格跑代码，结果直接显示在下面。做数据分析、写实验报告很顺手。

坑：在 A 环境装的 jupyter，切到 B 环境后看不到 B 的包——要给 B 装 ipykernel 并注册：python -m ipykernel install --user --name study。

08把环境交给别人

conda env export > environment.yml
conda env create -f environment.yml

第一条在自己的环境里导出，第二条在别人的电脑上还原。课程设计交作业、换电脑，都靠它。

坑：导出的 yml 里带 prefix:（你电脑的绝对路径），别人用之前删掉那一行。

09动手项目：给数据分析建个干净环境

要求：建一个叫 data 的环境（Python 3.11），装 numpy、pandas、matplotlib、jupyter，写个 notebook 读一个 CSV，画一张图。

验收：conda env list 能看到 data；notebook 里能 import 三个包；导出的 environment.yml 能在另一台机器还原。

10往哪走

环境弄顺之后，再去学 pip 的 requirements.txt、虚拟环境 venv（不装 conda 时的替代方案）。

一句话：Anaconda 解决的不是「装包」，是「这个项目用哪套包」——环境分得清，bug 就少一半。
