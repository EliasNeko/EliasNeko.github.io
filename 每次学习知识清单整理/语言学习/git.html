Git：代码的时光机

commit、branch、merge、冲突怎么解——你已经在用它了，但可能只用了三个命令。

10 节难度 低更新 2026-10-23

01三个区

Git 的绝大多数困惑，都来自没分清这三个区：

  • 工作区：你正在改的文件
  • 暂存区：git add 之后，准备提交的那部分
  • 仓库：git commit 之后，真正记进历史的那一版

文件从工作区 → 暂存区 → 仓库，一步一步走。

02第一次提交

git init
git status
git add index.html
git commit -m "第一个页面"

提交前先 git status，确认加进去的是你想加的文件。

坑：第一次提交前要配名字和邮箱，否则会提示 Please tell me who you are：git config --global user.name "名字"、git config --global user.email "邮箱"。

03看历史、看改动

git log --oneline
git diff
git diff --cached
git show 提交号

git diff 看「工作区 vs 暂存区」，git diff --cached 看「暂存区 vs 上次提交」。提交前扫一眼，能少很多「怎么把这个文件也提交了」。

04分支

git branch feature
git checkout feature
git switch -c feature2
git branch
git merge feature

分支就是「从某个点分出去的一条线」。改新功能先开分支，改坏了直接删，不影响主线。

坑：checkout 既能切分支又能还原文件，容易误操作；新版本用 switch 切分支、restore 还原文件，更清楚。

05合并冲突

两个人改了同一个文件的同一段，合并时 Git 不知道怎么选，就会在文件里留下标记：

<<<<<<< HEAD
你这一版的代码
=======
对方那一版的代码
>>>>>>> feature

处理办法：手动改成最终想要的样子，删掉 <<<<<<<、=======、>>>>>>> 这三行，再 git add + git commit。

坑：冲突标记没删干净就提交，代码里会残留这些符号，运行时报语法错误。

06远程仓库

git remote add origin https://github.com/用户名/仓库.git
git push -u origin main
git pull
git clone https://github.com/用户名/仓库.git

push 是把自己的提交传上去，pull 是把别人的拉下来。push 之前先 pull，能少很多冲突。

坑：push 被拒（fetch first）说明远端有你没有的提交，先 git pull --rebase 再 push，别硬推。

07.gitignore

node_modules/
*.log
.env
server/users.jsonl

写进 .gitignore 的文件，Git 就当没看见。密码、密钥、用户数据、依赖目录，都该在这里。

坑：已经提交过的文件，再加进 .gitignore 没用，要先 git rm --cached 文件名 再提交。

08撤销

git restore index.html          # 丢掉工作区的改动
git restore --staged index.html # 从暂存区撤回
git reset --soft HEAD~1         # 撤销上一次提交，改动留着
git revert 提交号               # 再做一次“反向提交”
坑：git reset --hard 会连工作区的改动一起删，且找不回来。用之前先 git status 看清楚。

09动手项目：把项目推上 GitHub

要求：给一个本地项目建仓库，写 .gitignore（排除 node_modules 和密码文件），提交，推到 GitHub，改一次再推一次。

验收：GitHub 网页上能看到两次提交；git status 显示干净；.gitignore 里的文件没出现在仓库里。

提示：推送失败先看提示是「认证」还是「冲突」，两种解法完全不同。

10往哪走

把 add/commit/push/pull 用顺，再看 git rebase、git stash、PR（Pull Request）流程。

一句话：Git 不是备份，是「让每一次改动都有理由」——提交信息写清楚，三个月后的你会感谢现在的你。
