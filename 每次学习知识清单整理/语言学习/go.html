Go：语法少，天生会并发

一个 goroutine 就是一条轻量线程。云原生那一整套，多半是它写的。

11 节难度 中等更新 2026-10-23

01它是什么

Go 是 Google 做的后端语言，语法少、编译快、天生支持并发。Docker、Kubernetes、很多云服务都是它写的。

它没有继承、没有泛型滥用的空间（新版有泛型，但用得克制），写法基本只有一种——所以团队里不太会为“风格”吵架。

适合谁：想写后端、又嫌 Java 那一套太重的人。

02装好、跑起来

去 go.dev 下载安装包，装完开新终端：

go version
mkdir hello && cd hello
go mod init hello

新建 main.go：

package main

import "fmt"

func main() {
    fmt.Println("你好，Go")
}
go run main.go
坑：一个目录里只能有一个 package main；入口函数必须叫 main，没有返回值、没有参数。

03变量和类型

var a int = 10
b := 20            // 短声明，只能在函数里用
const Pi = 3.14

var (
    name string = "咖啡"
    price int   = 32
)

Go 是强类型，int 和 int64 不能直接相加，要显式转换：int64(a)。

坑：声明了不用的变量会编译报错（不是警告）。用 _ 丢掉不需要的返回值。

04函数和多返回值

func div(a, b int) (int, error) {
    if b == 0 {
        return 0, fmt.Errorf("除数不能是 0")
    }
    return a / b, nil
}

q, err := div(10, 2)
if err != nil {
    fmt.Println("出错：", err)
}

多返回值是 Go 处理错误的根：结果 + error 一起返回，调用方必须自己判断。

05切片和 map

nums := []int{1, 2, 3}
nums = append(nums, 4)

stock := map[string]int{"咖啡": 10}
stock["茶"] = 4
if n, ok := stock["咖啡"]; ok {
    fmt.Println(n)
}
坑一：append 可能换一块新内存，所以要把返回值赋回去（nums = append(...)），直接 append(nums, 4) 不接返回值等于没加。
坑二：map 直接取不存在的键返回零值，不报错；用 v, ok := m[k] 才能分清「值是 0」和「没有这个键」。
坑三：map 不是并发安全的，多个 goroutine 同时写会直接 panic，要么加锁，要么用 sync.Map。

06结构体和方法

type Coffee struct {
    Name  string
    Price int
}

func (c Coffee) Describe() string {
    return fmt.Sprintf("%s 卖 %d 元", c.Name, c.Price)
}

func (c *Coffee) Raise(n int) {
    c.Price += n
}

值接收者 (c Coffee) 拿到的是副本，改不动原对象；要改就用指针接收者 (c *Coffee)。

07接口

type Speaker interface {
    Speak() string
}

type Cat struct{}
func (Cat) Speak() string { return "喵" }

func say(s Speaker) { fmt.Println(s.Speak()) }

say(Cat{})

Go 的接口是隐式的：只要方法签名对上了，就自动实现，不用写 implements。

坑：接口值为 nil 不代表它里面装的指针也是 nil。见过「明明判断了 err == nil 还是崩」的，多半是这个。

08错误处理

Go 没有 try/catch。错误就是一个普通返回值，一层层往上带：

data, err := os.ReadFile("a.txt")
if err != nil {
    return fmt.Errorf("读文件失败: %w", err)
}

%w 会把原始错误包起来，上层可以用 errors.Is / errors.As 判断具体类型。

坑：panic 是给「程序真的没法继续」用的，不要拿它当异常抛。网上很多教程随手 panic，别学。

09goroutine 和 channel

ch := make(chan string)

go func() {
    ch <- "咖啡好了"
}()

fmt.Println(<-ch)

一个 go 关键字就是一条轻量线程；channel 用来在它们之间传数据，代替共享内存加锁。

坑：循环里起 goroutine 时，别直接闭包捕获循环变量，要 go func(x int){...}(i) 传进去——否则所有 goroutine 可能拿到最后一个值（Go 1.22 之后每轮是新变量，但旧代码常见这个 bug）。

10动手项目：并发抓标题

要求：给 3 个网址，用 goroutine 同时抓，抓完打印每个网址的 HTTP 状态码；任何一个失败不能拖垮其他两个。

验收：总耗时接近最慢的那一个（不是三个相加）；断网时打印错误但不崩。

提示：

  • 用 net/http 的 http.Get，记得 defer resp.Body.Close()
  • 用 sync.WaitGroup 等三个都结束
  • 结果用 channel 收，或者每个 goroutine 写自己那格切片（提前分配好长度，别并发 append）

11往哪走

把标准库的 net/http、encoding/json 用熟，再去看 Gin 或 Fiber 这种框架，会快很多。数据库用 database/sql 加驱动。

一句话：Go 的哲学是「少即是多」——语法少，写法统一，出了问题大家都能看懂。
